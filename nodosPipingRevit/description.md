# Piping System Node Numbering Workflow

This document outlines the workflow for a pyRevit plugin designed to traverse a selected piping system, identify its nodes (elements like fittings, accessories, and equipment), and assign them sequential numbers using the `NetworkX` library for graph analysis.

## Overview

The core objective is to treat a Revit MEP piping system as a graph, where Revit elements are **nodes** and the pipes connecting them are **edges**. By building this graph in `NetworkX`, we can easily perform traversals (like Depth-First Search or Breadth-First Search) to determine a logical numbering sequence for the elements.

## Workflow Activities

### 1. User Selection & Initialization

* **Prompt User:** The plugin starts by asking the user to select a `PipingSystem` or a pipe/element belonging to a piping system.
* **Identify System:** If an individual element is selected, retrieve the associated `PipingSystem` using its properties (e.g., checking the `MEPSystem` property of its connectors).
* **Get Parameters:** Ask the user for the numbering prefix (e.g., "N-"), starting number, and the shared parameter name where the node number will be written (e.g., "Node_Number").

### 2. Graph Construction (NetworkX)

* **Initialize Graph:** Create an empty undirected or directed graph using `networkx.Graph()` or `networkx.DiGraph()`.
* **Traverse System:** Iterate through all elements within the selected `PipingSystem`. The `PipingSystem.Elements` property or a `FilteredElementCollector` restricted to the system's `Id` can be used.
* **Node Addition:** For every fitting, accessory, or mechanical equipment found, add it as a node to the graph. Use the element's `UniqueId` or `Id.IntegerValue` as the node identifier.
* **Edge Addition (Connector Traversal):**
  * For each element, retrieve its `ConnectorManager`.
  * Iterate through its `Connectors`.
  * For each `Connector`, check if `IsConnected` is true and if it's a physical connection (not logical).
  * Iterate through `Connector.AllRefs` to find connected elements.
  * If a connected element is a Pipe, follow the pipe to its other connector to find the next fitting/equipment. Add an edge in the NetworkX graph between the starting element and the element found at the other end of the pipe.

### 3. Graph Analysis & Numbering Sequence

* **Identify Start/Root Nodes:** Determine the starting point for numbering. This could be an equipment piece (e.g., a pump) or the open end of a pipe. In NetworkX, this might be a node with a degree of 1 (a leaf node) or a specific node selected by the user.
* **Determine Sequence:** Use a NetworkX traversal algorithm to generate a sequence of nodes.
  * `nx.dfs_preorder_nodes(G, source=start_node)` for a depth-first traversal.
  * `nx.bfs_tree(G, source=start_node)` for a breadth-first traversal.
* **Handle Branches:** Decide how branches should be numbered (e.g., finish the main line first, or number down branches as they are encountered). The choice of DFS vs. BFS often dictates this.

### 4. Parameter Updating (Revit API)

* **Start Transaction:** Open a `Transaction` in the Revit document because modifying element parameters requires transaction control.
* **Assign Values:** Iterate over the ordered sequence of nodes generated by NetworkX.
* **Write to Parameter:** Retrieve the corresponding Revit `Element` for each node identifier. Find the specified shared/project parameter (e.g., "Node_Number") and set its value (e.g., "N-01", "N-02").
* **Commit Transaction:** Commit the transaction to save changes to the Revit model.

## Relevant Revit API Classes & Functions (2023+)

The following classes from the `Autodesk.Revit.DB` and `Autodesk.Revit.DB.Plumbing` namespaces are critical for this workflow:

### Element and System Classes

* **`PipingSystem`**: Represents the logical system. Use its properties to gather the elements it contains.
* **`Pipe`**: Represents the pipe element. While pipes act as edges in our conceptual graph, they are usually skipped during node numbering, but their connectors are essential for finding the next node.
* **`FamilyInstance`**: Most fittings (`BuiltInCategory.OST_PipeFitting`), accessories (`OST_PipeAccessory`), and equipment (`OST_MechanicalEquipment`) are instances of this class.

### Connector Connectivity

* **`ConnectorManager`**: Obtained from an element (e.g., `FamilyInstance.MEPModel.ConnectorManager`). It holds all the connectors for that element.
* **`ConnectorSet`**: A collection of `Connector` objects returned by the `ConnectorManager`.
* **`Connector`**: Represents a connection point. Critical properties/methods include:
  * `IsConnected`: Boolean indicating if something is attached.
  * `AllRefs`: A `ConnectorSet` containing all other connectors attached to this one. This is the primary mechanism for traversing from one element to the next.
  * `ConnectorType`: Helps differentiate between Physical, Logical, etc. Ensure you traverse physical connections.
  * `Owner`: Gets the element that owns the connector.

### Utility Classes

* **`FilteredElementCollector`**: Used to gather all pipes, fittings, or systems in the document or specific view.
* **`Transaction`**: Required to wrap the parameter modification phase.
* **`Parameter`**: The class representing the specific parameter on an element where the node number will be written. Use `element.LookupParameter("ParameterName")` to access it.

## NetworkX Integration Note

Since pyRevit uses IronPython (often Python 2.7 or 3.4/3.8 via CPython engines depending on the pyRevit version), ensure the version of NetworkX you use is compatible with the underlying Python environment. If using the newer CPython engines in pyRevit 4.8+, standard NetworkX installations usually work well.
